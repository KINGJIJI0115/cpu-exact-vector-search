# 无损整数 SIMD 候选路径

状态：已合入正式 mode7。性能目标是否达到，以当前源码匹配的完整 78 项验收及原始数据重算为准。

## 适用条件与精确性

数据库和本次查询的所有坐标均须是区间 [0,255] 内的整数，维度须为 1–258。建立索引时逐项检查数据库，搜索时逐项检查查询。任一条件不满足，就使用已有浮点直接平方差路径。分流依据数据表示条件和输入规模，不读取数据集名称，也不缓存查询答案。

编码把 float32 中可精确表示的整数转成 unsigned byte，不做量化舍入。每个 AVX2 32 位通道对应一个候选向量的两个维度：将 16 个字节零扩展成 16 个有符号 16 位数，减去广播查询，再用 `VPMADDWD` 求相邻两维的平方和，累加到 32 位整数中。八个通道同时处理八个候选。奇数维度补零。

差值在 [-255,255] 内；两维平方和至多 130050。总距离至多 `258 × 255² = 16776450 < 2²⁴`，因此不发生有符号 32 位溢出，转换成 float32 输出仍精确。Top-K 使用距离、ID 的字典序处理并列。这项论证只覆盖满足检查条件的输入；浮点回退保持原有数值容差验证口径。

`formal_verify_byte.py` 使用 Z3 检查差值范围、两维平方和范围、总和范围、奇数维补零四项算术引理。它没有验证完整 C++、内存布局、SIMD 指令翻译或机器码。实现另由 `test_goal_bytes.py` 的独立 float64 穷举参考检验，包括 0/255 极值、维度与候选尾部、并列、K=N，以及分数、负数、超过 255 和超过 258 维时的回退。

## 延续已有实现的部分

沿用自研 AoSoA、查询分组、缓存分块、流式 Top-K 和距离/ID 排序规则。新增整数数据布局及整数 SIMD 内核；不调用 BLAS 或 Faiss。另有普通浮点候选：单次向下调整堆、候选缓冲筛选、显式预取、25 维固定展开和 64 字节对齐。

## 成本与比较边界

候选实现保留原浮点布局，以支持非整数查询回退，同时额外保存字节布局。额外有效数据量约为 `N × 2⌈D/2⌉` 字节，不能把字节扫描量下降写成整个索引内存下降。索引构建检查与布局转换在预处理阶段；构建耗时单独记录。查询条件检查、查询编码、搜索、候选选择和输出分配均计入查询计时。

Faiss 比较对象为相同 float32 输入上的 IndexFlatL2 默认、直接距离、强制 BLAS，以及在合法整数输入上精确的 QT_8bit_direct 路径。此方案适合本来就满足整数条件的精确检索输入，不代表对任意连续浮点向量或 Faiss 所有索引类型的普遍优势。

## 验收

`goal_scope.json` 固定 26 个全库配置及判据；`goal_screen.py` 只用调参查询筛选候选。最终实现必须在冻结源码后，对 3 批不重叠的查询分别重复 7 次，每一项的中位时间均不高于同轮最快 Faiss 路径，并通过正确性检查。筛选成功不等于最终验收成功。

`oracle_cache.py` 仅复用不计时的独立 float64 穷举参考结果。缓存键包含全部数据库/查询字节、形状、算法源码和 NumPy 版本；缓存损坏或输入变化会重新计算。实际检索方法每轮均执行，不复用其输出。缓存可删除，复现时会重建。

128 维采用编译期展开，Q=1/2/3–4/≥5 分别使用 1/2/4/8 查询内核；其他合法维度仍使用通用整数路径。GloVe25 的浮点路径也经过训练查询上的候选筛选，独立性由排除调参查询后的验证建立。
