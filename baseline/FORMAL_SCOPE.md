# 形式化验证范围

formal_verify.py 对 N=1…8、K=1…N 共 36 种规模执行符号验证。输入不是随机样本，而是互异的任意实数序键；每次加入候选后保留最小 K 个的状态转移用 Z3 If 表达式表示。独立规格要求第 r 个输出属于输入且恰有 r 个输入小于它。求解规格否定式，UNSAT 表示该规模中不存在反例。

序键抽象对应 C++ 的有限距离与唯一 ID 的字典序：即使距离相等，ID 也确定总序。排序后的保留集合抽象了最大堆；该验证不逐指令模拟 std::push_heap/pop_heap，不证明浮点距离计算、AVX2 或任意规模 C++ 实现。它是算法模型的有界形式化验证，不是端到端程序形式化证明。

提供 36 个 SMT-LIB 文件、求解器版本、源码哈希和 JSON 结果。另将保留最小值故意改成最大值，要求求解器返回 SAT 反例，用于避免把永远返回 UNSAT 的错误测试误认为有效验证。

运行：python3 formal_verify.py。Ubuntu 依赖：python3-z3。验证失败或超时会返回非零状态并中止自动流程。

参考：https://z3prover.github.io/papers/programmingz3


## 无损整数路径的算术引理

formal_verify_byte.py 另用 Z3 验证四项反例查询：合法字节坐标的差值适合有符号 16 位；两维平方和不超过 130050；D≤258 时总和小于 2^24；奇数维的零填充不改变距离。运行输出均需 UNSAT，否则流程失败。IEEE float32 可精确表示该范围内的整数和。

前提由实现中的数据及查询检查建立，并由独立 double 参考测试覆盖边界。四个引理不证明这些检查或整段 SIMD 机器码实现正确，也不覆盖普通浮点回退。它们与原来的 36 项有界 Top-K 模型分别保存，不能简单宣称“整个程序完成形式化验证”。
